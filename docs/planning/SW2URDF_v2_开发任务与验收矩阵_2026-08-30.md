## 总体结论

功能代码、schema、CLI、Robot Bundle、ROS/ros2_control、Isaac 适配器、现代 UI 接线、安装器
载荷和分层 CI 已实现。本机能够执行的 Core/CLI/Python/schema/可复现 Bundle 验证必须全部通过；
Windows/SolidWorks、ROS/Gazebo 和 Isaac GPU 是独立专用环境验收项，工作流已提供，但没有运行
证据时不得写成“已实机通过”。

## 关键实现要求

### P0/P1：模型和语义

- 所有核心数值使用 SI；禁止 NaN/Infinity；几何尺寸和质量必须为正；
- Link/Joint 名称、ID、parent/child、mimic graph 必须一致；
- STEP、固定装配和零自由度不自动生成 Joint 类型；
- SolidWorks Mate 只能生成带证据的建议，用户确认前阻断交付；
- UI 在“下一步”阶段执行已显式选择的 Mate 辅助，失败回滚 Joint 状态，成功后要求逐项复核；
- 单旋转自由度只能建议运动族，界面暂显示 `continuous`，用户必须判断是否改为有界 `revolute`；
- 人形模型的 actuator、传动和关节限制由工程 profile 明确定义。

### P2/P3：可移植交付

- Bundle 不保存开发机绝对路径；拒绝 `..`、rooted path、symlink、大小写碰撞，以及输出目录
  包含源 URDF、网格或补充报告的覆盖写；
- 清单必须覆盖全部载荷，profile/header/validation 摘要必须与实际内容一致；
- `SOURCE_DATE_EPOCH` 支持确定性构建；同输入两次 Bundle 应一致；
- CLI 输出机器可读 JSON，配置错误和内部错误使用不同退出码。

### P4/P5：ROS 与控制

- ROS 2 使用 ament、`ros_gz_sim` 和现代 Gazebo，不生成旧 `gazebo_ros` 路径；
- 只接受维护矩阵中的 ROS/Gazebo 组合；
- ros2_control joint 必须存在且可动，controller joint 必须属于 hardware 配置；
- 内置 controller 仅生成已知参数契约；未知插件需项目自行提供并评审；
- runtime gate 要观察 controller_manager 和目标 controllers 为 `active`。

### P6：Isaac / RL

- Bundle 模型必须声明许可证；Isaac Sim/Lab 分别精确 pin 版本；
- converter 使用当前 importer API，API 字段缺失时 fail closed；
- USD 名称不安全时在进入 Isaac profile 前阻断，不静默改名造成控制映射漂移；
- actuator group 唯一覆盖全部可动 Joint，gain/limit 必须为有限正值；
- 生成成功、USD 加载、physics step、RL task 验收分别留证。

### P7/P8：桌面端和交付

- UI 提供 Lyrical/Jetty 与 Jazzy/Harmonic 两个受控组合；
- Isaac Lab 勾选依赖 Isaac Sim，且必须选择 actuator profile；
- 所有 v2 导出先使用隔离 source staging，完成后删除，不把中间 ROS 1 结构写入用户输出目录；
- 根目录始终生成本次 v2 `export_report.md`（包括 Bundle-only），所选 ROS 包保留包内副本；
  报告只记录最终 Bundle/ROS 资产路径，包内报告写入后刷新 ROS 包校验和；
- Bundle 中的 CAD mesh report 只保存可移植路径；
- 安装器包含 `OSURDF.Core.dll`、Newtonsoft.Json、schema、OpenUSD/MuJoCo adapter 与固定运行时、
  第三方声明和 MIT/Apache-2.0 许可证正文；
- 旧仓库内置的 EOL `log4net 2.0.8` 不进入安装包，改为锁定并校验当前受维护的
  `log4net 3.4.0` NuGet 包；
- Release 构建只允许 immutable worktree、locked dependency 和经过哈希核验的 payload。
- Windows 候选构建必须先用 `Test` 配置运行 TestRunner，再封装无测试代码的 `Release` DLL；
- 自托管 workflow 仅允许人工触发，checkout 不持久化凭据，所有 job 都设超时；
- `solidworkstools.dll` 属于专有运行时，Draft 转公开前必须完成 Dassault/SolidWorks 许可审核；

## 验收命令

当前分支的可移植与资产运行时验收入口如下：

```bash
dotnet test tests/OSURDF.Core.Tests/OSURDF.Core.Tests.csproj -c Release --filter "Category!=PinnedMuJoCoRuntime"
dotnet build src/OSURDF.Cli/OSURDF.Cli.csproj -c Release
python3 -B -m unittest discover -s tools/usd_adapter/tests -p 'test_*.py'
python3 -B -m unittest discover -s tools/mujoco_adapter/tests -p 'test_*.py'
```

固定 MuJoCo 运行时门禁另外设置 `SW2URDF_MUJOCO_BIN` 与 `SW2URDF_MUJOCO_VERSION`，并只执行
`Category=PinnedMuJoCoRuntime`；TRX 必须证明恰好 1 项被执行并通过。端到端还必须覆盖：URDF
import → profile overlay → validate → 两次确定性 Bundle → verify → ROS1/ROS2 export → OpenUSD
生成并重开 stage → MJCF 编译、规范保存、重载和一步零控制推进。

## 本机完成记录

### 生成能力

- 插件可生成 ROS1/ROS2 功能包、OpenUSD 机器人资产和 MuJoCo MJCF 资产；Robot Bundle 仅作为
  系统临时目录内的私有规范暂存，不是用户交付物；
- 四种用户目标按所选目录进行可恢复事务发布，顶层报告明确记录本次目标；未选择目标的旧目录
  保留且不计入本次验证；
- CLI Release 与插件 Test/Release 候选均由固定 .NET SDK、locked NuGet 依赖和哈希锁定的资产
  运行时构建。

### 自动化验证

- Core 单元/安全回归覆盖严格 JSON、非有限数、路径重叠、reparse point/symlink 拒绝、确定性
  Bundle、ROS 导出以及多目标事务提交/回滚/中断恢复；
- OpenUSD adapter 测试验证 stage 结构；固定 OpenUSD 运行时生成并重新打开正式 `robot.usd`；
- MuJoCo adapter 测试验证入口；固定官方 MuJoCo 工具对 `robot.xml`、`scene.xml` 完成编译、规范
  保存、重载和一步零控制推进；专用 xUnit 门禁禁止零测试或跳过伪绿；
- JSON、workflow、安装器载荷、第三方许可、Release 草稿及源码格式由独立门禁检查。

### 实际应用运行验证

- 本机已完成 Windows 编译和固定资产运行时检查，但本轮未执行 Live SolidWorks COM 交互，也未做
  SolidWorks 跨版本矩阵；
- 未在实际 ROS/Gazebo、Isaac Sim/Isaac Lab 或用户 MuJoCo 控制器/接触/任务工程中验证。资产生成
  成功和上述最小官方运行时检查不能替代这些下游验证；
- 未经人工测试确认不得创建公开 GitHub Release。旧安装包测试不能替代本轮候选重建。

## 发布门槛

1. S1/S2 本机与 hosted CI 全绿；
2. Windows Release x64 和插件测试全绿；
3. SolidWorks 2023 安装、加载、三类代表装配导出通过；
4. ROS 目标组合构建、Gazebo 启动和 controller active；
5. Isaac 精确版本转换、USD 重开、Lab smoke 通过；
6. 安装包 SHA-256、payload provenance、开源许可证、`solidworkstools.dll` 再分发权和 release
   notes 审核；
7. 人工批准后才允许合并、Tag 和公开 Release。

“安装包以前测过”只覆盖旧候选；本轮新增 Core、schema 和 adapter 后必须重新构建并执行新的
payload/安装验证，不能沿用旧安装包结论。
