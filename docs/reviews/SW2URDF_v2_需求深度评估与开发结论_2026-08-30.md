# SW2URDF v2 需求深度评估与开发结论

## 对两份评审报告的判断

两份报告指出的方向成立：旧工具的核心问题已经不只是 UI，而是模型语义、可追溯性、现代 ROS
和仿真资产链缺少统一契约。需要修正的一点是，不应把“关节识别”描述成对任意 CAD 的自动能力。

同事提出的两个现实约束都是正确的：

1. STEP 等中间格式通常没有 Joint/Mate 语义；
2. 人形机器人设计者经常使用固定装配，CAD 是否可动与最终 URDF 是否有关节没有必然关系。

因此，最可靠的产品定位不是“自动识别所有关节”，而是“让工程师高效、可审计地定义关节，并在
存在可靠 Mate 证据时提供可拒绝的建议”。这既照顾普通用户，也避免基础设施向下游制造隐蔽错误。

## 已采用的产品决策

- 规范中保留未知状态，不以默认 `fixed` 掩盖语义缺失；
- 每个 Joint 记录来源、证据、引用和人工确认；
- Mate 检测只作为原生可动装配的辅助流程；
- Robot Bundle 成为单一真源，ROS/Isaac 都从其派生；
- ros2_control 和 Isaac actuator 参数使用显式 profile；
- Isaac Sim/Lab 使用精确版本门禁，不承诺“所有版本通用”；
- UI 引导填写许可证、维护者和版本，便于开源再分发；
- CI 按 hosted、Windows/SolidWorks、ROS runtime、Isaac GPU 分层。

## 基础设施还应长期坚持的原则

- 可扩展的是 schema migration 和 exporter adapter，不是无边界猜测；
- 对外稳定的是 Bundle 契约、CLI 退出码和验证报告，不绑定某一代 UI；
- 兼容矩阵只写经过验证的组合，上游新版本通过专用门禁后再升级；
- 失败必须可定位到字段、资源或 profile；warning 不得掩盖阻断性错误；
- 模型许可证属于模型作者，工具许可证不能代替模型许可证；
- 开源仓库许可证也不能代替 SolidWorks 专有运行时的再分发授权，安装器只可先生成 Draft 候选；
- 公开 Release 必须同时具备源码、构建、payload、运行时和人工审批证据。
- 依赖不能因为“旧工具一直这么带”而继续冻结在 EOL 二进制；安装包只接收锁定、校验并在目标
  Framework 上通过回归的受维护版本。本轮已把 `log4net 2.0.8` 交付引用升级到 3.4.0。

## 风险与后续维护

本轮开发可以一次性完成代码路径，但长期维护仍不可一次性结束。SolidWorks COM、ROS/Gazebo、
Isaac importer 和 Isaac Lab 都会演进，至少应在每次目标版本升级时更新兼容矩阵并运行对应
self-hosted workflow。对闭环、并联、柔性体、transmission 和复杂传感器的支持应以独立 schema
扩展进入，不能塞进简单 Joint 自动识别。
